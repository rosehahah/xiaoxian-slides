# 演示内容数据格式

构建器把 UTF-8 编码的 JSON 内容转为可独立播放的 HTML。文本是纯文字，不解析 HTML 或 Markdown。长句拆开写，不用空格模拟排版。

## 最小示例

```json
{
  "title": "把想法讲清楚",
  "author": "你的名字",
  "slides": [
    {
      "layout": "cover",
      "title": "把想法讲清楚",
      "body": "一次清楚、有重点的分享",
      "theme": "blue",
      "notes": "开口：介绍今天要解决的问题。展开：说明听众能得到什么。收束：从一个真实场景开始。",
      "seconds": 45
    },
    {
      "layout": "end",
      "title": "下一次，只讲一个重点",
      "body": "选一份素材，现在开始。",
      "theme": "lime"
    }
  ]
}
```

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 字符串，必填 | 演示标题，用于浏览器标题与导出 |
| `author` | 字符串，可选 | 作者或讲述者 |
| `subtitle` | 字符串，可选 | 演示副标题 |
| `slides` | 数组，必填 | 按播放顺序排列的页面，1–100 页 |

## 每页字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `layout` | 字符串，必填 | `cover`、`statement`、`split`、`cards`、`steps`、`timeline`、`quote`、`end` |
| `title` | 字符串，必填 | 本页重点；建议不超过 36 个中文字 |
| `body` | 字符串，可选 | 正文或解释；建议不超过 80 个中文字 |
| `kicker` | 字符串，可选 | 小标签，例如“第一部分”“一个真实案例” |
| `theme` | 字符串，可选 | `paper`、`blue`、`ink`、`lime`、`coral`；默认 `paper` |
| `items` | 对象数组，可选 | 结构见下；双栏、卡片、步骤与时间线使用 |
| `image` | 字符串，可选 | 本地图片路径，相对 JSON 文件所在目录解析；也可用绝对路径或受支持格式的 base64 data URI |
| `imageAlt` | 字符串，可选 | 图片的简短说明；图片有信息含义时填写 |
| `notes` | 字符串，可选 | 讲者备注，建议包括开口、展开、收束 |
| `seconds` | 数字，可选 | 本页建议讲述秒数，大于 0、不超过 3600 |

`items` 每项格式：

```json
{
  "title": "先选一个重点",
  "body": "这一页只回答一个问题。"
}
```

条目标题必填，正文可选。`items` 仅用于 `cards`、`split`、`steps`、`timeline`。双栏最多 2 项；卡片必须有 2–4 项；步骤与时间线必须有 2–5 项。超出时拆页。条目标题建议控制在 16 个中文字内，正文控制在 50 个中文字内。未知字段、版式、主题和不支持的字段组合会报错；较长文本会警告，但不会被悄悄截断。

## 图片与离线

`image` 只用于 `cover` 和 `split`；`split` 的图片与条目二选一。支持本地 PNG、JPEG、WebP、GIF，以及这些格式的 base64 data URI；单图不超过 15 MB。SVG 请先转成 PNG。构建器会将图片内嵌进 HTML，生成后移动 HTML 不会丢图。不支持远程图片 URL；先使用用户已有、可用且有权限的本地素材。图片在 JSON 中示例：

```json
{
  "layout": "split",
  "title": "让图像解释真实现场",
  "body": "一句话说明图像与观点的关系。",
  "image": "images/workshop.jpg",
  "imageAlt": "参与者围绕桌面讨论方案"
}
```

将 JSON 与 `images` 目录一起保存，后续修改时仍能重新构建。图片内嵌会增加 HTML 大小；用与展示需求相符的图片，避免无必要地放入超大原图。

## 选择合适的承载方式

- `cover` / `statement` / `quote` / `end`：主要使用 `title`、`body`、`kicker`。
- `split`：使用图片与文字，或 2 项 `items` 表达对比。
- `cards` / `steps` / `timeline`：使用 `items` 组织并列或顺序内容，`body` 可作简短引导。

构建完成后查看实际页面；字段有效不代表排版一定合适。修改 JSON 后，需要重新运行构建器，已有 HTML 才会更新。
